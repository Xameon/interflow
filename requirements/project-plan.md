# Project Plan — Social Network for Interest-Based Communities

## 1. Project Goal

The goal of the project is to create a social network that connects people through shared interests and hobbies.  
Users will be able to create communities, share posts, comment, and interact with others who share similar passions.

---

## 2. Developer

- **Developer:** Solo developer
- **Roles:** Planning, development, testing, deployment, and maintenance
- **Tech Stack:** Next.js (main platform), TypeScript, Postgres, Firebase

---

## 3. Methodology

The project follows an **Agile/Scrum-inspired** approach using **bi-weekly sprints**.  
Each sprint has a clear goal, deliverables, and a short progress report.  
Task management and prioritization are handled in **GitHub Projects**.

---

## 4. Main Development Phases

1. **Environment Setup** – create repository, configure TypeScript, ESLint, Firebase.
2. **Core Functionality** – authentication, posts, guest browsing.
3. **Feature Expansion** – comments, communities, subscriptions.
4. **Optimization & Responsiveness** – performance testing and UI/UX refinement.
5. **Deployment & Testing** – deploy MVP, collect feedback, and fix bugs.

---

## 5. Risk Matrix

| #   | Risk                                       | Probability | Impact | Mitigation Plan                                |
| --- | ------------------------------------------ | ----------- | ------ | ---------------------------------------------- |
| 1   | Work overload as a solo developer          | High        | High   | Break tasks into smaller parts, daily planning |
| 2   | Technical issues with Firebase integration | Medium      | High   | Early integration tests, review documentation  |
| 3   | Data loss or Postgres failures             | Low         | High   | Regular backups                                |
| 4   | Lack of time for testing                   | Medium      | Medium | Reserve buffer time at the end of each sprint  |
| 5   | UI design uncertainty                      | Low         | Medium | Early wireframes                               |

---

## 6. Quality Management

- Code quality ensured via **ESLint**, **Prettier**, and **TypeScript**
- Manual testing of core user flows before deployment
- Code and documentation stored in **GitHub**
- Weekly self-review and progress evaluation

---

## 7. Communication & Planning

- All tasks are documented in **Backlog.md**
- Progress is tracked in **GitHub Projects**
- Sprint reports are created every 2 weeks

---

## 8. Expected Results

Within 4–6 weeks, the goal is to deliver a **functional MVP** that includes:

- User registration and authentication
- Ability to create, edit, and view posts
- Image uploads via Firebase
- Community creation and management
- Guest browsing of public content
